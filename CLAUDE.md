## Project Overview

**RosTooling** is a Model-Driven Engineering (MDE) Eclipse plugin suite that brings ROS (Robot Operating System) concepts into Ecore metamodels and Xtext-based DSLs. It supports both ROS 1 and ROS 2, and produces textual editors, validators, and code generators as Eclipse plugins.

Maintained by Fraunhofer IPA. Full documentation: https://ipa320.github.io/RosTooling.github.io/

## Build System

Maven + **Tycho** (Eclipse OSGi plugin build). All commands must be run from the repository root (`git/RosTooling/`). For source development in Eclipse IDE, use **Eclipse 2024-09** with Maven 3.9.9 — `docu/Installation.md` references older versions that are no longer correct.

```bash
# Full build (compile + package)
mvn clean verify -f plugins/de.fraunhofer.ipa.ros.parent/pom.xml

# Skip tests (faster iteration)
mvn clean verify -f plugins/de.fraunhofer.ipa.ros.parent/pom.xml -DskipTests
```

Key versions (set in parent POM):
- Java compile target: **21**
- Xtext: **2.42.0**
- Tycho: **4.0.12**
- MWE2: **2.22.0** (for Ecore/Xtext code generation workflows)

P2 dependency repositories (Eclipse 2025-12, Xtext 2.42.0 update site) are declared in the parent POM — no local Maven repo resolves these.

## Running Tests

The test modules are **commented out** in `plugins/de.fraunhofer.ipa.ros.parent/pom.xml`. To run tests, uncomment the relevant modules first:

```xml
<module>../de.fraunhofer.ipa.ros.xtext.tests</module>
<module>../de.fraunhofer.ipa.rossystem.xtext.tests</module>
```

Test plugins use `eclipse-test-plugin` packaging (JUnit via Tycho Surefire). There is no way to run a single test class from the command line without an Eclipse test harness; tests run during `mvn verify`.

## Architecture

All source lives under `plugins/`. Each subdirectory is a separate OSGi bundle (Eclipse plugin).

### Layer 1 — Metamodels (Ecore)
| Plugin | Role |
|--------|------|
| `de.fraunhofer.ipa.ros` | Core ROS metamodel (`model/ros.ecore`, `model/PrimitivesTypes.ecore`) |
| `de.fraunhofer.ipa.rossystem` | System composition metamodel (`model/rossystem.ecore`) |

These define the abstract syntax (concepts: packages, nodes, topics, parameters, interfaces). Generated EMF Java classes live in `src-gen/`.

### Layer 2 — Generic Xtext DSL
| Plugin | Role |
|--------|------|
| `de.fraunhofer.ipa.ros.xtext` | Generic Xtext grammar over the ROS metamodel (`.ros` files) |
| `de.fraunhofer.ipa.rossystem.xtext` | System-level DSL (`.rossystem` files) |

Each grammar plugin has sibling bundles:
- `.xtext.ide` — platform-independent IDE services (content assist, formatting)
- `.xtext.ui` — Eclipse UI integration (editor, outline, quick fix)

### Layer 3 — ROS Version–Specific DSLs
| Plugin | Role |
|--------|------|
| `de.fraunhofer.ipa.ros1.xtext` | ROS 1–specific grammar extension |
| `de.fraunhofer.ipa.ros2.xtext` | ROS 2–specific grammar extension |

Each also has `.ide` and `.ui` siblings.

### Layer 4 — Utilities & Editors
| Plugin | Role |
|--------|------|
| `de.fraunhofer.ipa.roscode.generator` | Xtend-based code generators producing ROS2 C++ and Python node skeletons from `.ros` models (`RosCodeGenerator.xtend`, `Ros2CppCodeGenerator.xtend`, `Ros2PythonCodeGenerator.xtend`); generated Java lives in `xtend-gen/` |
| `de.fraunhofer.ipa.ros.plugin` | Validators, code generators, utility classes |
| `de.fraunhofer.ipa.ros.edit` | EMF Edit provider (tree editor label/property support) |
| `de.fraunhofer.ipa.ros.editor` | Base graphical editor scaffolding |
| `de.fraunhofer.ipa.ros.sirius` | Sirius-based graphical diagram editor |
| `de.fraunhofer.ipa.rossystem.edit` | EMF Edit for ROSsystem metamodel |
| `de.fraunhofer.ipa.rossystem.editor` | ROSsystem tree editor |
| `de.fraunhofer.ipa.rossystem.deployment` | Deployment support (currently disabled in parent POM) |
| `de.fraunhofer.ipa.ros.feature` | Eclipse feature (packages all plugins for distribution/update site) |

## Key Development Notes

- **Code generation**: Ecore-derived Java sources and Xtext parser/formatter code are in `src-gen/` inside each metamodel/grammar plugin. Xtend template output goes to `xtend-gen/`. Neither should be hand-edited; `src-gen/` is regenerated by MWE2 workflows (`*.mwe2`), `xtend-gen/` by the Xtend compiler.
- **Xtext grammar changes**: Modifying a `.xtext` grammar requires re-running its MWE2 workflow to regenerate the parser, serializer, and formatter in `src-gen/`.
- **Feature packaging**: `de.fraunhofer.ipa.ros.feature` aggregates all plugins for the Eclipse update site; add new plugins there when introducing new bundles.
- **Disabled modules**: `rossystem.deployment`, `rossystem.model.combination`, `ros.model.spec.check`, and both test modules are commented out in the parent POM — they exist on disk but are excluded from the build.
